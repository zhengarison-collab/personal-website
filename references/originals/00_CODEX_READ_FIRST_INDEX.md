## 1. 项目当前核心

### 网站定位
这是 Terry 的专属个人数字展示空间。首页/主空间本身是 Terry 所在的地方，访客从这里进入不同主题房间，再回到 Terry。

核心路径：

`Terry / Main Space → Topic Room → Return → Terry / Main Space`

网站不需要把 Terry 压缩成单一职业标签。不同房间承载不同身份、经历、兴趣与项目。

当前核心 slogan：

**All of this is me. / None of it is all of me.**

### 当前主题房间
1. About / 个人简介
2. Work / 简历 / 过往案例
3. Novels / 长篇小说
4. PTG / 个人 AI App
5. Terry Studio / 佛牌
6. Freeframe Studio / 当前工作

### 当前主空间视觉
- 全屏沉浸式动态场景，弱化“普通网页”感。
- 写实数字人 Terry 是主空间中心。
- 当前最新 UI 视觉参考为 **毛绒 / 柔软 / 立体 / 有触感的 3D 对象**。
- 粉色空间 + 克莱因蓝 + 柠檬黄是当前主要色彩方向。
- 原视频中出现的透明玻璃/水晶物体可视为 **交互位置与运动占位素材**，不要自动当成最终 UI 风格。
- UI 形状可以不同，但全站交互语言、运动阻尼、反馈逻辑、排版系统应保持统一。

### 2026-09-04 最终视觉对齐（最高视觉优先级）

**GLOBAL SCOPE — 这是全站“视频 × 交互 UI”的统一制作标准，不是某一张图、某一帧或某一个视频的特例。**

`03_FINAL_VISUAL_TARGET.jpeg` 只是用于说明“正确融合效果”的视觉样例，不要求其他镜头复制它的具体构图、人物姿势或三个 UI 造型。Codex 必须把同一套融合标准举一反三应用到：
- `welcome zone.MP4` 的全部交互时段；
- `mainlinevedio1~5` 的全部交互时段；
- `ending bye.MP4` 中任何出现网页交互对象的时段；
- 后续新增的所有 Main Space 交互视频；
- 任何 Topic Room 中采用“视频/人物场景 + 真交互 UI”组合的镜头。

允许并期待 Codex 根据每个镜头的内容、动作、空间和交互目的，自主设计不同的 UI 对象、形态、颜色、数量、位置与动效。`03_FINAL_VISUAL_TARGET.jpeg` **只定义最终呈现质量，不定义固定 UI 造型**；图中的几个毛绒对象只是示例，不应被机械复制成全站组件库。唯一必须保持的是同等级的空间融合与视觉完成度。任意镜头一旦出现“背景视频 + 浮层按钮 / HUD / 贴纸 / 静态 PNG”的感觉，即视为该镜头未达标。

根目录 `03_FINAL_VISUAL_TARGET.jpeg` 是当前 Main Space 的**最终视觉目标参考**。当它与更旧的水晶/玻璃/普通网页方案冲突时，以这张图及本节为准。

目标体验：
- 场景本身以视频呈现；人物与毛绒空间具有真实摄影/CG 质感。
- 毛绒 UI 是**真实网页交互对象**，但视觉上必须像原本就存在于视频世界里的实体。
- 需要匹配画面透视、尺度、Z 深度、光向、软阴影、环境色、景深/模糊、运动节奏与人物动作。
- 需要处理前后遮挡：当人物的手、身体或场景前景应该挡住 UI 时，UI 必须被正确遮挡；反之亦然。
- UI 出现、膨胀、漂浮、点击反馈必须与视频时间轴/人物动作建立锚点，不允许无关地悬浮在屏幕坐标上。
- 原视频透明玻璃/水晶只作为位置、动作和时序参考；最终应移除、遮盖、替换或通过前景/遮罩处理干净。

**验收失败情形：**
- HTML 卡片/按钮直接叠在视频上，明显像 HUD、贴纸或悬浮层。
- 静态 PNG 图标贴在画面上充当交互。
- UI 没有场景光影、透视和遮挡关系。
- 人物在视频里做出“召唤/触碰”动作，但 UI 的出现位置、时间或运动与动作无关。

实现技术可由 Codex 自主选择。优先考虑 WebGL/Three.js、透明 Canvas、DOM 可访问点击层、视频分层/人物 matte、遮罩、FFmpeg 预处理等组合；目标是最终感知效果，不强制某一技术栈。

## 2. 状态与读取优先级

### Status
| 状态 | 含义 |
|---|---|
| `CURRENT` | 当前有效、可作为现阶段依据 |
| `CURRENT_SOURCE` | 当前可用的源素材/视频，但其中部分视觉可能只是占位 |
| `REFERENCE` | 参考、历史案例、证据或素材池 |
| `DUPLICATE` | 重复副本；使用指定 canonical 文件 |
| `LEGACY` | 历史方案，仅在追溯时使用 |
| `IGNORE` | 系统垃圾、构建残留或无内容价值 |

### Priority
| 优先级 | Codex 行为 |
|---|---|
| `P0` | 项目入口级；先确认它，但目录本身也**禁止递归全读** |
| `P1` | 仅在对应任务中读取 |
| `P2` | 素材池；先看索引，确实需要视觉证据时少量抽样 |
| `P3` | 大体积/高成本原始文件；没有明确任务要求不得读取 |
| `IGNORE` | 不读取 |

## 7. 素材池读取策略

### 图片目录
1. 先读目录名称与本索引。
2. 若任务只需要“知道这里有什么”，停止。
3. 若需要设计/挑图，先抽样 3–8 个代表素材。
4. 只有抽样不足以完成任务时再扩大范围。
5. 不因随机文件名而默认逐张识别。

### 视频目录
1. 先看文件名、大小、用途。
2. 小型当前主空间视频优先于大型历史成片。
3. 只有涉及时序、镜头、遮挡、锚点、素材剪选时才深入视频。
4. P3 视频需显式任务理由。

### PDF / Markdown / RTF
文字文档通常信息密度最高，优先于同目录的大批图片与视频。

## 9. Codex 的直接建站目标

**现在直接进入设计 + 开发，不再先走 Work 整理阶段。**

Codex 可以在开发过程中内部维护必要的 `MASTER_SPEC / SITE_MAP / INTERACTION_SPEC / CONTENT / ASSET_MANIFEST / DESIGN_SYSTEM / ACCEPTANCE_CRITERIA`，但这些是辅助工程文件，不是本轮主要交付。

本轮主要交付应是：

1. 可运行的个人网站工程。
2. 完整 Main Space：Welcome → Idle/Mainline → 可交互毛绒 UI → Topic Room → Return → Main Space。
3. 6 个 Topic Room 的可运行结构，并按索引选择性填入现有内容。
4. 真正可点击、可 hover/touch/press、有状态反馈的 UI。
5. 视频与交互 UI 的空间融合/遮挡/时序合成方案及实现。
6. 响应式桌面与移动端适配；视觉完整性优先于模板化响应式。
7. 开发说明、素材依赖和仍需人工补充的极少数明确事项。

不要以“先整理完全部资料”为前置条件；证据够用就开始实现，并边开发边按任务点读素材。
